What the course is

How a computer turns a description of a three-dimensional world into a picture, and, increasingly, how it learns that world from pictures. The first half builds the foundation every renderer shares: vectors, rotations, affine transformations, scene graphs, cameras and projection, rasterization, meshes, textures and local illumination. A bridge week states the rendering equation and the physically based materials and ray tracing that solve it. The second half is the neural era: networks and embeddings, the space of images, diffusion models, learned scenes (neural radiance fields and Gaussian splatting), and generative 3D and video. About 40 % of the class is on the neural side.

No prior graphics or Unity experience is assumed. Programming maturity in a C-family language and comfort with linear algebra at the level of vectors and matrices are.

Materials

  • The course text (24 chapters, free, on the course site): the primary reading. Every lecture, homework and quiz draws its numbers from it.
  • The demo library (on the course site): interactive demos with live readouts; the WebGL homework skeletons are built on it.
  • Tools, by track: Unity 6000.3.11f1 (the pinned version; install through Unity Hub, personal license) or a browser and a local static server for the WebGL track; Python 3 with NumPy for the two neural homeworks, or JavaScript.
  • Canvas: homework submission, grades, announcements, and the single source of truth for every due date.

Quiz and exam items are computational: which entry of the matrix, which pixel wins the depth test, what the diffuse term is after the light moves, how many samples halve the error. Each quiz includes items that require what the week's homework computed. Bring a pencil; no devices during quizzes or exams.

Homework: two tracks

Each assignment states what to build and the numbers a correct build reproduces (taken from the text's worked examples), and provides a skeleton in each of two tracks. You choose per assignment.

TrackWhat you getWhat you submit
Unitya Unity project with the functions to implement stubbedthe project folder, zipped, without Library/
WebGLone JavaScript file that mounts into the course's demo library, with the implementation stubbedthat file
Python (HW7 and HW8 only, in place of Unity)a notebook with the functions stubbedthe notebook, run
Implement and replace. Each assignment names engine helpers that are off limits (for example Transform.LookAt and Matrix4x4.LookAt in Unity, Matrix4.lookAt and Quaternion.slerp in three.js). You build the operation from primitives (dot, cross, normalize, matrix products) and check it against the engine's version. The engine is the answer key, not the tool.
Late work. Every student has two late tokens. A token, declared in the submission comment, extends one homework by 24 hours with no penalty. Beyond tokens, late homework loses 10 % per day for up to three days and is not accepted after that. Quizzes and exams have no tokens and no make-ups.

Collaboration and integrity

  • Homework: discuss freely, write your own code. Name in the submission comment anyone you worked with and any tool (including AI assistants) you used, and be ready to explain every line you submit.
  • Quizzes and exams: individual, closed book, on paper. They are 80 % of the grade for that reason.
  • UW's academic integrity policy applies; a first violation on homework is a zero on that assignment and a report, on an exam a failing grade in the course.
