## Triangles: always planar, always convex

Every real-time surface, a character, a terrain, a car, is a **triangle mesh**. Two reasons the hardware insists:

- a triangle is always **planar**: three points define exactly one plane, so the surface between them is unambiguous
- a triangle is always **convex**: three edge functions decide inside or outside, the fixed test the GPU runs billions of times a second

A quad's four corners can be non-planar (bent), and its fill is ambiguous. Split it into two triangles and both problems vanish.

## A mesh is two arrays

<img src="../../textbook/figures/mshd-two-arrays.svg" style="height:380px" alt="   vertices v[]         indices t[]  (triples)
     v0 = (…)             t = [ 0, 3, 1,   ← triangle 0
     v1 = (…)                   1, 3, 4,   ← triangle 1
     v2 = (…)                   … ]">

- a **vertex array**: the positions (and later normals, UVs), each vertex stored **once**
- an **index array**: flat triples, each naming one triangle by pointing into the vertex array

## Winding picks the front face

<img src="../../textbook/figures/mshd-winding.svg" style="height:300px" alt="WebGL, seen from above: (0, 3, 1) runs counter-clockwise, front face, drawn.
WebGL, seen from below: (0, 3, 1) runs clockwise, back face, culled.

- index order decides which side is the **front**; the **back** is usually culled
- WebGL's front is **counter-clockwise**; Unity's is **clockwise**, with z flipped, so the **same triples face up in both**
- wrong order: the triangle vanishes, or lights from the inside

## Row-major indexing

For an `$n \times n$` grid, the vertex at (`row`, `col`), both running `$0 \ldots n$`, lives at one formula:

<div class="tex" role="img" aria-label="index(row, col) = row · (n + 1) + col">
\[ \text{index}(\text{row}, \text{col}) = \text{row} \cdot (n + 1) + \text{col} \]
</div>

At `$n = 2$` that is `$3 \cdot \text{row} + \text{col}$`: (0, 0) is 0, (1, 1) is 4, (2, 2) is 8. One quad sits at each (`row`, `col`) for both in `$0 \ldots n-1$`, with four corners:

<div class="tex" role="img" aria-label="v00 = index(row, col)      v01 = index(row, col+1)
v10 = index(row+1, col)    v11 = index(row+1, col+1)">
\[ \begin{aligned} v_{00} &= \text{index}(\text{row},\ \text{col}) & \qquad v_{01} &= \text{index}(\text{row},\ \text{col}+1) \\ v_{10} &= \text{index}(\text{row}+1,\ \text{col}) & \qquad v_{11} &= \text{index}(\text{row}+1,\ \text{col}+1) \end{aligned} \]
</div>

Every triangle is written in these four names: no magic numbers.

| ---- | -------------- | --------------- |
| (0, 0) | (0, 3, 1) | (1, 3, 4) |
| (0, 1) | (1, 4, 2) | (2, 4, 5) |
| (1, 0) | (3, 6, 4) | (4, 6, 7) |

## Two arrays cannot find neighbors

Editing, smoothing and simplifying keep asking:

- which **triangles** touch this vertex? which **vertices** ring it?
- which triangle is **across** this edge? is the edge on a **boundary**?

The index array has one way to answer: scan every triangle.

| one pass over the bunny, every vertex asking for its triangles | triangles examined |
| -------------------------------------------------------------- | ------------------ |
| scan the index array each time: `$34{,}834 \times 69{,}451$` | 2,419,256,134 |
| walk half-edges: `$3F$` | 208,353 |

11,611 times fewer, for the same answers.

## An edge, stored twice

<img src="../../textbook/figures/mshd-he-anatomy.svg" style="height:262px" alt="triangles t1 = (1, 3, 4) and t2 = (1, 4, 2) share the edge v1–v4.
h5 runs from v4 to v1 inside t1; its twin h6 runs from v1 to v4 inside t2; next of h5 is h3, from v1 to v3.
h5: to = 1, face = 1, next = 3, twin = 6">

- each edge splits into two **half-edges**, one per triangle, each directed the way its triangle winds
- a triangle has exactly 3, so the grid has `$3F = 24$`
- its 8 interior edges have two; its 8 boundary edges have one, with `twin` = −1

## The half-edge ADT

class HalfEdge {
    public int to;     // the vertex it points at
    public int face;   // the triangle it belongs to

class HalfEdgeMesh {

## Edges of a triangle: follow next

<img src="../../textbook/figures/mshd-he-face-walk.svg" style="height:205px" alt="triangle t1: faceEdge[1] = h3. h3 from v1 to v3, next h4. h4 from v3 to v4, next h5. h5 from v4 to v1, next h3, back at the start">

<div class="code-tabs">

```csharp
static List<int> EdgesOfFace(HalfEdgeMesh m, int f) {
    var edges = new List<int>();
    int start = m.faceEdge[f];
    int h = start;
    do {
        edges.Add(h);
        h = m.he[h].next;
    } while (h != start);
    return edges;
}
```

```javascript
function edgesOfFace(m, f) {
  const edges = [];
  const start = m.faceEdge[f];
  let h = start;
  do {
    edges.push(h);
    h = m.he[h].next;
  } while (h !== start);
  return edges;
}
```

</div>

Reading `to` along the walk gives the corners: 3, 4, 1.

<div class="code-tabs">

```csharp
static List<int> FacesAtVertex(HalfEdgeMesh m, int v) {
    var faces = new List<int>();
    int start = m.vertexOut[v];
    int h = start;
    do {
        faces.Add(m.he[h].face);
        int back = m.he[m.he[h].next].next;   // comes back into v
        h = m.he[back].twin;                  // leaves v, one triangle over
    } while (h != start);
    return faces;
}
```

## Boundaries: where the walk stops

<img src="../../textbook/figures/mshd-he-boundary.svg" style="height:290px" alt="the plain walk from h1 at v3: h0 has twin −1, only t0 is found. rotate back first, to h12: now all of them: t4, t1, t0. half-edges with no twin: one loop of 8: 3, 6, 7, 8, 5, 2, 1, 0">

- at the edge of a mesh `twin` is −1, and the plain ring loop would read `he[-1]`
- rotate **back** first (`twin`, then `next`) to the half-edge with no twin, then walk forward
- half-edges with no twin chain into closed **loops**, one per hole: the bunny's five, 80, 42, 40, 39 and 22 edges long

## Walking an open fan

<div class="code-tabs">

```csharp
static int StartOfFan(HalfEdgeMesh m, int v) {
    int first = m.vertexOut[v];
    int h = first;
    while (m.he[h].twin != -1) {
        h = m.he[m.he[h].twin].next;     // one triangle the other way
        if (h == first) return first;    // a closed ring: any start will do
    }
    return h;
}
static List<int> FacesAtAnyVertex(HalfEdgeMesh m, int v) {
    var faces = new List<int>();
    int start = StartOfFan(m, v);
    int h = start;
    do {
        faces.Add(m.he[h].face);
        h = m.he[m.he[m.he[h].next].next].twin;
    } while (h != start && h != -1);
    return faces;
}
```

```javascript
function startOfFan(m, v) {
  const first = m.vertexOut[v];
  let h = first;
  while (m.he[h].twin !== -1) {
    h = m.he[m.he[h].twin].next;     // one triangle the other way
    if (h === first) return first;   // a closed ring: any start will do
  }
  return h;
}
function facesAtAnyVertex(m, v) {
  const faces = [];
  const start = startOfFan(m, v);
  let h = start;
  do {
    faces.push(m.he[h].face);
    h = m.he[m.he[m.he[h].next].next].twin;
  } while (h !== start && h !== -1);
  return faces;
}
```

</div>

One loop for both cases: a closed ring ends at `start`, an open fan at −1.

## Building the links from two arrays

<img src="../../textbook/figures/mshd-he-build.svg" style="height:186px" alt="t1: (1,3) → h3, (3,4) → h4, (4,1) → h5. t2: (1,4) → h6, (4,2) → h7, (2,1) → h8. reverse the key: (4,1) finds (1,4), so h5 and h6 are twins. (2,1) finds no (1,2), so h8 keeps twin −1">

- one pass over the corners: each half-edge is filed under its directed edge `(a, b)`
- one pass over the edges: reverse the key; if `(b, a)` exists, those two are **twins**; if not, it is a **boundary** edge
- `$O(F)$` with a hash map, from the two arrays any mesh file holds
- a directed edge that arrives **twice** means a non-manifold edge or a flipped triangle: report it

## Building the links: the code

<div class="code-tabs">

```csharp
static HalfEdgeMesh Build(int[] tris, int vertexCount) {
    var m = new HalfEdgeMesh();
    m.he = new HalfEdge[tris.Length];
    m.vertexOut = Enumerable.Repeat(-1, vertexCount).ToArray();
    m.faceEdge = new int[tris.Length / 3];
    var byEdge = new Dictionary<(int, int), int>();   // (a, b) -> the half-edge from a to b
    for (int h = 0; h < tris.Length; h++) {
        int t = h / 3, k = h % 3;
        int a = tris[h], b = tris[3 * t + (k + 1) % 3];
        m.he[h] = new HalfEdge { to = b, face = t, next = 3 * t + (k + 1) % 3, twin = -1 };
        byEdge[(a, b)] = h;
        if (m.vertexOut[a] == -1) m.vertexOut[a] = h;
        m.faceEdge[t] = 3 * t;
    }
    foreach (var pair in byEdge) {                    // reverse each key to find the twin
        int other;
        if (byEdge.TryGetValue((pair.Key.Item2, pair.Key.Item1), out other)) m.he[pair.Value].twin = other;
    }
    return m;
}
```

```javascript
function build(tris, vertexCount) {
  const m = new HalfEdgeMesh();
  m.vertexOut = new Array(vertexCount).fill(-1);
  const byEdge = new Map();                 // "a,b" -> the half-edge from a to b
  for (let h = 0; h < tris.length; h++) {
    const t = Math.floor(h / 3), k = h % 3;
    const a = tris[h], b = tris[3 * t + (k + 1) % 3];
    const e = new HalfEdge();
    e.to = b;  e.face = t;  e.next = 3 * t + (k + 1) % 3;
    m.he[h] = e;
    byEdge.set(a + ',' + b, h);
    if (m.vertexOut[a] === -1) m.vertexOut[a] = h;
    m.faceEdge[t] = 3 * t;
  }
  for (const [key, h] of byEdge) {          // reverse each key to find the twin
    const [a, b] = key.split(',');
    if (byEdge.has(b + ',' + a)) m.he[h].twin = byEdge.get(b + ',' + a);
  }
  return m;
}
```

## The half-edge interface

| query | walk | steps |
| ----- | ---- | ----- |
| edges and corners of a triangle | `next` until back at the start | 3 |
| where `h` starts | `to` of `next.next` | 2 |
| triangle across `h` | `face` of `twin` | 2 |
| corner opposite `h` | `to` of `next` | 2 |
| triangles, neighbors, valence of `v` | `next.next.twin` from `vertexOut` | valence |
| every edge once | `h` where `h < twin`, or no twin | `$3F$` |
| the rim of a hole | `next`; while it has a twin, `next` of the twin | rim length |

The cost is storage: 4 integers per half-edge, `$12F + V + F$`. For the bunny, 937,697 integers against the index array's 208,353: 4.5 times. GPUs never see it; they get the two arrays.


---

## Euler's formula checks a mesh

For a closed surface, `$V - E + F = 2 - 2g$` (`$g$` = holes through it); each boundary loop subtracts 1 more.

| mesh | `$V - E + F$` | | |
| ---- | ------------- | - | - |
| cube | `$8 - 12 + 6$` | 2 | closed, genus 0 |
| the 2×2 grid | `$9 - 16 + 8$` | 1 | one boundary loop |
| icosphere | `$162 - 480 + 320$` | 2 | closed, genus 0 |
| Stanford bunny | `$34{,}834 - 104{,}288 + 69{,}451$` | −3 | genus 0, so 5 boundary loops |

The bunny has **five holes in its base** (loops of 80, 42, 40, 39 and 22 edges): where the scanner could not see.

## Normals: which way the surface faces

Positions give a surface its **shape**; they say nothing about which way it **faces**. Lighting needs that direction at every point:

- brightness depends on the angle between the **normal** and the light (the illumination topic)
- a position array with no normals renders **unlit**: a silhouette, no shading

So every vertex carries a **unit normal** beside its position. The question is where it comes from, and the answer is a cross product.


---

## A face normal is a cross product

A triangle is flat, so it has **one** normal. Cross two edges from a shared corner:

<div class="tex" role="img" aria-label="faceN = (v1 − v0) × (v2 − v0)">
\[ \mathbf{n}_{\text{face}} = (v_1 - v_0) \times (v_2 - v_0) \]
</div>

The **winding** fixes the sign: listed front-facing, the cross points out the front. The first triangle `$(0, 3, 1)$` of the flat grid:

<div class="tex" style="font-size:0.74em" role="img" aria-label="edge1 = v3 − v0 = (0, 0, 1.5)      edge2 = v1 − v0 = (1.5, 0, 0)
faceN = edge1 × edge2 = (0, 2.25, 0)   →   normalize → (0, 1, 0)">
\[ \begin{aligned} e_1 &= v_3 - v_0 = (0,\ 0,\ 1.5) \qquad e_2 = v_1 - v_0 = (1.5,\ 0,\ 0) \\ e_1 \times e_2 &= (0,\ 2.25,\ 0) \;\to\; (0,\ 1,\ 0) \end{aligned} \]
</div>

The cross's **length is twice the triangle's area**: `$2.25 = 2 \cdot \tfrac12 (1.5)(1.5)$`.


---

## From face normals to vertex normals

Each interior vertex is shared by several faces. Its normal is the normalized **sum** of theirs:

<div class="tex" role="img" aria-label="n[i] = normalize( Σ faceN(f) )     over every face f that touches vertex i">
\[ \mathbf{n}_i = \text{normalize}\Big( \sum_{f \,\ni\, i} \mathbf{n}_{\text{face}}(f) \Big) \]
</div>

<div class="code-tabs">

```csharp
Vector3[] sums = new Vector3[v.Length];
for (int t = 0; t < tri.Length; t += 3) {
    int a = tri[t], b = tri[t + 1], c = tri[t + 2];
    Vector3 face = Vector3.Cross(v[b] - v[a], v[c] - v[a]);   // length = 2 x area
    sums[a] += face;   sums[b] += face;   sums[c] += face;
}
```

```javascript
const sums = v.map(() => [0, 0, 0]);
for (let t = 0; t < tri.length; t += 3) {
  const a = tri[t], b = tri[t + 1], c = tri[t + 2];
  const face = cross(sub(v[b], v[a]), sub(v[c], v[a]));       // length = 2 x area
  sums[a] = add(sums[a], face);  sums[b] = add(sums[b], face);  sums[c] = add(sums[c], face);
}
```

</div>

Unnormalized crosses give a bigger face a bigger vote. HW5 and the demo do this; Sung's code normalizes each face first, so every face votes equally.

## Sweeping a profile into a surface

<div style="display:flex; align-items:center; gap:10px; justify-content:center">
<img src="../../textbook/figures/mesh-sweep.svg" class="media-shot" style="height:300px" alt="a profile polyline beside the rotation axis, and the wireframe surface of revolution it sweeps, rings connected by meridians">
<div class="tex" style="font-size:0.66em" role="img" aria-label="vertex(i, j) = R_y(θ_j) · profile[i],   θ_j = j · Δθ,   Δθ = 2π / S
R_y(θ) = [ cos θ  0  sin θ ; 0  1  0 ; −sin θ  0  cos θ ]">
\[ \begin{gathered} \text{vertex}(i, j) = R_y(\theta_j)\, \text{profile}[i] \\[4pt] \theta_j = j\,\Delta\theta, \quad \Delta\theta = \frac{2\pi}{S} \\[8pt] R_y(\theta) = \begin{bmatrix} \cos\theta & 0 & \sin\theta \\ 0 & 1 & 0 \\ {-\sin\theta} & 0 & \cos\theta \end{bmatrix} \end{gathered} \]
</div>
</div>

**P** profile points and **S** rotation steps give a `$P \times S$` grid of vertices, in quads like the flat grid. The index `$j$` wraps modulo `$S$`, so the surface closes.

## Degenerate case: the poles

## The quadric error, worked

Garland and Heckbert (1997): the cost of moving a vertex to `$p$` is the sum of squared distances to the planes of its original triangles, `$\sum (\mathbf{n}_k \cdot p + d_k)^2$`.

The lifted 2×2 grid, edge 4–1 (center to an edge vertex), seven planes:

| merge at | cost |
| -------- | ---- |
| vertex 4 | 0.160 |
| vertex 1 | 1.457 |
| the midpoint | 0.404 |
| the optimum (0, 0.338, 0), from a 3×3 system | **0.135** |

Edge 0–1, on the flat border: merge at vertex 1, cost **0**. Each vertex keeps one 4×4 matrix, the sum of its planes' quadrics; a collapse adds two matrices. Cheap enough for millions of edges.

## Mesh files: OBJ

Wavefront **OBJ**: text, one vertex or face per line, indices starting at **1**. The lifted 2×2 grid:

```text
   v -1.5 0 -1.5        f 1 4 2
   v  0   0 -1.5        f 2 4 5
   v  1.5 0 -1.5        f 2 5 3
   v -1.5 0  0          f 3 5 6
   v  0   0.4 0         f 4 7 5
   v  1.5 0  0          f 5 7 8
   v -1.5 0  1.5        f 5 8 6
   v  0   0  1.5        f 6 8 9
   v  1.5 0  1.5
```

- `f 1 4 2` is the triangle `(0, 3, 1)`: add 1 to every index
- normals and texture coordinates are separate lists, joined per corner as `f 1/1/1 4/4/4 2/2/2`
- no binary form, no scene graph, no animation; readable everywhere
